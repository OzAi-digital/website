AI coaching for engineering

AI transformation for dev teams.

A separate coaching journey for software teams moving from writing code manually to using AI tools, coding agents, and agent supervision as part of disciplined delivery.

AI Coaching overview
Why this is separate

Developer AI changes the delivery model, not just personal productivity.

Developers are not only drafting text. They are changing code, tests, dependencies, architecture, and production systems.

The goal shifts from writing every line to specifying, steering, reviewing, and supervising AI agents.

Engineering teams need new practices for context, test design, code review, security, ownership, and traceability.

Dev team maturity

The journey is from autocomplete to agent supervision.

0

Manual delivery

AI is not in the workflow, or usage is ad hoc and untrusted.

1

Assisted coding

Developers use AI for snippets, explanations, tests, and refactors.

2

Tool fluency

Teams use Cursor-style IDE workflows, repo context, prompts, and review loops.

3

Agentic delivery

Agents implement bounded tasks with tests, diffs, and human approval.

4

Supervision

Engineers orchestrate multiple agents, manage quality gates, and own outcomes.

What we teach

Teams need practices for tools, agents, and engineering judgement.

Developers

Prompting with repo context, Cursor-style workflows, tests-first tasks, refactoring, and review.

Tech leads

Task decomposition, architecture constraints, agent briefs, PR quality, and delivery risk.

EMs and PMs

AI-assisted planning, estimation changes, acceptance criteria, and delivery governance.

QA and security

Test strategy, dependency review, secrets handling, vulnerability checks, and regression control.

Platform teams

Approved tools, environment setup, logging, policy, model access, and internal enablement.

Core practices

The skill is supervising work, not blindly accepting generated code.

ContextGive agents the right files, constraints, architecture notes, acceptance tests, and non-goals.
Task shapeSplit work into bounded changes with expected diffs, test commands, and rollback paths.
ReviewRead diffs, inspect assumptions, challenge generated tests, and verify behavior locally.
Quality gatesUse tests, linting, type checks, security scans, and human approval before merge.
TraceabilityCapture prompts, agent decisions, commits, known risks, and handover notes.
Rollout model

A dev team rollout should start with low-risk work and build trust.

  1. BaselineCurrent SDLC, tools, repo shape, test health, security rules, and AI access.
  2. Tool setupApproved IDE agents, terminal agents, repo context, policies, and team templates.
  3. Workflow labsBug fixes, test generation, refactors, docs, code review, and migration tasks.
  4. Agentic pilotsBounded tasks implemented by agents with tests, diffs, and human supervision.
  5. Operating modelTeam playbooks, review gates, lead routines, metrics, and continuous improvement.
What the dev team gets

Transformation needs team artefacts, not just tool licenses.

Tooling policyApproved AI tools, model access, data boundaries, and usage rules.
Agent brief templatesReusable task specs for bugs, refactors, tests, docs, and migrations.
Review checklistHow engineers evaluate generated code, tests, dependencies, and risk.
Workflow playbookPatterns for Cursor-style IDE use, terminal agents, PRs, and handoff.
Quality gatesTest, lint, type, security, and approval expectations before merge.
Adoption rhythmOffice hours, lead reviews, metrics, and backlog of better agent tasks.
Recommended first conversation

Start with the SDLC, not the tool demo.

A 60-minute discovery session should identify the team's current delivery flow, repo quality, test maturity, security constraints, approved tools, and the first low-risk agentic pilot.
