Acceptance tests

Written before build. Signed off before launch.

If we can’t write a test for it, it isn’t ready to build — and we’ll tell you.

  1. 01

    Inputs

    Approved samples that represent normal and messy real cases.

  2. 02

    Outputs

    Exact fields, sections, labels, source links and destinations.

  3. 03

    Exceptions

    What happens when data is missing, confidence is low or a request is out of scope.

  4. 04

    Human approval

    Where staff review, edit or reject before anything reaches a customer or system of record.

  5. 05

    Cost and latency

    Operating thresholds for model usage, runtime and retries.

  6. 06

    Audit trail

    Logs, sources, prompt and workflow versions sufficient to investigate any run.

Connections

Assistants that can reach your systems — only the parts they should.

Most useful workflows need to read from or write to something: a CRM, an inbox, a shared drive, a booking system. We connect them through narrow, permissioned connectors — including Model Context Protocol (MCP) servers, so the same connector works with ChatGPT, Claude, Gemini or Copilot as your tools change.

  • Least privilege

    Each connector exposes only the actions the workflow needs; write actions are separate from read.

  • Approval on writes

    Anything that changes a record or contacts a customer can require a person’s approval.

  • Logged

    Every call is recorded with who, what and when.

  • Yours

    Connectors run in your accounts and are documented in the handover.
