Five gates. No vague AI project.

Every build is deliberately bounded before work starts. If the workflow cannot be tested, it is not ready to build.

1

Scoping call

Define the workflow, source systems, users, risks, and the smallest useful outcome.

2

One-page SoW

Scope, price, timeline, acceptance tests, handover assets, and operate option in plain language.

3

Build sprint

Working demos every one to two weeks. Deterministic logic where possible, AI where it adds value.

4

Acceptance

You sign off against the written criteria, not vibes, demos, or moving goalposts.

5

Operate

Monitoring, cost checks, model or prompt updates, and documentation while the workflow beds in.

Acceptance tests are written before build.

We agree how the workflow will be tested using sample inputs, expected outputs, edge cases, and human review rules.

Input Coverage

Approved sample files, emails, forms, tickets, records, or prompts that represent normal and messy real-world cases.

Output Format

Exact fields, sections, labels, confidence markers, source links, file formats, or handoff destinations the workflow must produce.

Exception Rules

What happens when source data is missing, confidence is low, the request is out of scope, or a policy-sensitive case appears.

Human Approval

Where staff must review, edit, approve, reject, or escalate before AI-assisted work reaches a customer or system of record.

Cost & Latency

Reasonable operating thresholds for model usage, runtime, queueing, retries, and background processing.

Audit Trail

Logs, source references, prompt versions, workflow versions, and handover notes sufficient to investigate issues after launch.

Operate is lightweight, but not optional thinking.

AI workflows change as models, prompts, documents, and user behaviour change. We keep the support simple and transparent.

What Gets Handed Over

The build is delivered with the practical artefacts needed to use it, support it, and decide what to improve next.

Working Workflow

Deployed automation, assistant, extraction flow, drafting tool, or integration in the agreed environment.

Source & Config Notes

Repository, prompts, environment variables, provider choices, connected systems, and deployment instructions where applicable.

User Guide

How staff should use the workflow, what it is not designed to do, and when to escalate or review output manually.

Acceptance Record

The agreed tests, sample cases, known limitations, accepted tradeoffs, and any follow-up backlog.
