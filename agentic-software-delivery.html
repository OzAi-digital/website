The operating model

Seven stages. Each one can say no.

  1. 01
    Engineer

    Stage 1: Specify

    An engineer writes the issue: the behaviour wanted, acceptance criteria, constraints, non-goals and the tests that will prove it.

    Stops if

    The criteria can't be tested.

  2. 02
    Agent

    Stage 2: Plan

    The agent proposes an approach and the files it expects to change. Larger work is split into small, reviewable changes.

    Stops if

    The plan touches areas outside the issue.

  3. 03
    Agents

    Stage 3: Implement

    Coding agents write the change and its tests on an isolated branch, with access only to that repository and a sandboxed environment.

    Stops if

    The agent can't make the tests pass inside its budget. It escalates rather than guessing.

  4. 04
    CI

    Stage 4: Automated gates

    CI runs the full suite: unit and integration tests, coverage on changed code, type checks, linting, static security analysis, dependency vulnerability and licence checks, secret scanning, and performance or load budgets where the system has them.

    Stops if

    Any gate fails. Gates are not skipped to meet a date.

  5. 05
    Reviewer agent

    Stage 5: Independent review

    A reviewer agent, configured separately from the author, checks the change against the issue, our coding standards, security patterns and the architecture notes, and records findings on the pull request.

    Stops if

    Findings are unresolved.

  6. 06
    Senior engineer

    Stage 6: Human approval

    A senior engineer reads the diff, the tests and the review, and approves the merge, or sends it back. No change merges without this.

    Stops if

    The engineer isn't satisfied. That's the point.

  7. 07
    Pipeline

    Stage 7: Release and operate

    Changes deploy through the pipeline with monitoring, alerting and agreed service-level objectives. Rollback is a known, tested step.

    Stops if

    Error budgets or health checks fail after deploy.

Traceability throughout. Every release links back to its commits, every commit to its review and issue, every issue to the requirement it serves.
